WHAT BITWISE REPRODUCTION MISSES IN A GPU
REACTOR DATA PIPELINE
Shodh AI Research
ABSTRACT
A GPU reactor pipeline reproduced a reference dataset byte for byte, including a
heat flux with the wrong sign. We examine two questions raised by this result.
First, what makes two generated records identical? In three eight-GPU replays
over the same 256 samples, changing the output schedule preserved every tra-
jectory and interface array but changed 41 metadata hashes. A matched-operand
control traced three affected records to a batch-dependent FP64 reduction. Sec-
ond, does an identical record satisfy its declared physics? Both exporters sampled
a jacket cell’s stored zero temperature. Across all 16 saved frames of two retained
483 samples, the archived flux was −128.250 kW/m2. Evaluating the same heat-
transfer law at adjacent fluid faces gave +12.038 to +12.144 kW/m2, outward
as expected for warmer fluid. We provide the frame-level measurements and a
notice identifying the affected legacy channel. On an H100, handwritten Triton
and precision-emulating TorchInductor both matched the eager transport words at
1.314 and 1.404 ms per call, respectively, versus 47.387 ms for eager. Full-node
throughput varied across the three rounds.

address the numerical primitive. Our reference is an existing PyTorch reduction whose rounded

Deterministic GPU execution. PyTorch’s deterministic-algorithms mode concerns repeated exe-

separately describes how computing on batches and slices can yield different rounded results ( Py-

changes size. We track that distinction through spatial reduction, time integration and serialization.
Stencil fusion and floating-point contraction. Halide separates the stencil computation from its
execution schedule (Ragan-Kelley et al., 2013). Triton exposes tiling and memory access to the ker-
nel author ( Tillet et al. , 2019). TorchInductor generates fused kernels from PyTorch graphs ( Ansel
et al. , 2024). On NVIDIA GPUs, multiply-add contraction can replace two roundings with one
(Whitehead & Fit-Florea , 2011). CUDA exposes -fmad=false to disable contraction in NVCC
(NVIDIA, 2025). We test the corresponding Triton setting and precision emulation in Inductor on
the same eager arithmetic target. This comparison isolates what handwritten code adds once the
compiler also meets the wordwise criterion.

Kernel decomposition. The eager solver batches samples on one GPU. Its transport path stacks
fields and materializes shifted arrays, neighbor selections and gradients through separate tensor op-
erations. We keep the eight fields in one contiguous FP64 allocation [8, B, Z, Y, X]. The transport
kernel views field and sample as one leading index k. Each Triton program owns one (k, z, y) row
tile, and adjacent lanes address adjacent x cells. At B = 8 and X = Y = Z = 128 the launch grid
is (1, 16,384, 64) with 128 elements and four warps per program. The axial offsets in elements are
±1, ±X and ±Y X . Bounds masks protect the loads and a separate active mask selects the neighbor
or center value.
Each program accumulates advection and diffusion in x, y, z order and writes one transport result
per field element. A second, pointwise kernel owns a spatial tile for one sample. It reads the eight
old state values and their transport terms, computes rates and sources, and writes updated state in
place. Keeping a separate transport buffer ensures that all neighbor reads in Eq. ( 2) see the old state.

4.2 R ECOVERING THE EAGER ARITHMETIC
An early implementation failed all six FP64 stencil checks on two small grids. Two details were
consequential. First, a fused multiply-add can round once where eager multiplication followed by
addition rounds twice. We compile with enable_fp_fusion=False and retain parentheses,
including the rounded subtraction c+a − 2ci before adding c−a . Second, the tested PyTorch CUDA
scalar division followed reciprocal multiplication. On four million FP64 inputs, CUDA division
by the scalar spacing differed from NumPy division for 1,833,864 values. Direct CUDA division
and CUDA multiplication by the precomputed reciprocal matched on every input. Multiplication,
addition and subtraction controls each had zero mismatches.
The kernel therefore loads 1/h and 1/h2 from an FP64 device buffer. It promotes the stored FP32
velocity to FP64 before multiplying by the gradient. For reaction rates, a separate probe compared
500,000 exponential evaluations over the clamped range and narrower intervals around zero. Triton’s
tested exponential paths matched the PyTorch CUDA result word for word. These comparisons
cover the tested exponential and transport outputs. Saved trajectories exercise the reaction update
after conversion to FP32.

4.3 S NAPSHOT AND HOST PIPELINE
The impeller speed ramps and then holds constant. The optimized solver reuses the velocity, pres-
sure and CFL calculation when the speed repeats. It accumulates reaction-bound violations on the
GPU and checks at save boundaries and completion, avoiding per-step scalar synchronization. Ten
snapshot arrays share one FP32 transfer on a side stream. A reusable pinned host buffer feeds pre-
allocated final frame arrays. Host workers can pack, audit and write one sub-batch while the GPU
advances the next. Separate processes build fluxes and reuse invariant surface quantities. This over-
lap can keep two sub-batches resident, so the feasible schedule depends on node-level host memory.
A single packed trajectory occupies 2.25 GiB at the stated shape. The 13-channel FP32 flux ar-
ray adds 1.625 GiB. Across 256 samples the two logical arrays alone amount to 992 GiB before
compression. Compressed file sizes and physical transfer volumes depend on chunking and data
values.

5.2 B OTH EXPORTERS GIVE THE WRONG DIRECTION OF JACKET HEAT FLOW
Under the archive’s sign convention, a positive heat flux leaves the fluid. For an active fluid cell i
sharing a face with the jacket, the specified heat-transfer law gives
q′′i→j = hJ (Tf,i − TJ ). (3)
The eager and optimized exporters both index temperature with the jacket mask. All 7,920 marked
cells in each retained frame belong to the solid. The stored temperature there is a zero fill value.
Substituting it into Eq. ( 3) gives 450(0 − 285) = −128,250 W/m2. The code reads the opposite side
of the interface from the one the law specifies. Reversing the sign of the archived values would still
leave their magnitude wrong.

7 C ONCLUSIONS AND OUTLOOK
A record intended for exact regeneration needs a specification for every persisted diagnostic, includ-
ing its batch partition or an order-independent summation rule. The 41 changed metadata hashes
show the practical consequence of leaving that choice implicit. The heat-flux comparison asks a dif-
ferent question of the very same acceptance procedure. Both exporters reproduced heat flowing the
wrong way because they read the same solid-cell fill value. A boundary test with a known tempera-
ture ordering catches the defect even without a second implementation. We retain the legacy digests
as a record of the benchmark and identify the flux channel in the dataset notice. A replacement data
release would need its own version, reference hashes and a comparison of integrated boundary heat
with the discrete solver source.
